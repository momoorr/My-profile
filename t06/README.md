# ALEPH T06 — 플랜두씨 다이어리 1

이 버전은 **실제 Supabase 프로젝트 연결 전 단계의 웹앱 소스**입니다. 백엔드 연결 전에는 저장 기능을 비활성화하며 성공을 가장하지 않습니다.

## 사전 설정
1. 기존 다른 프로젝트가 아닌 **T06 전용 새 Supabase 프로젝트**를 만듭니다. 이 작업은 사용자 소유 조직에서 생성하고 비용·공개범위를 확인한 뒤 진행해야 합니다.
2. Supabase Dashboard → Authentication → Providers에서 **Anonymous Sign-ins**를 활성화합니다. 사용자에게 로그인 화면은 표시하지 않지만 내부적으로 고유 익명 사용자 ID가 생성됩니다. 브라우저 세션 삭제/기기 변경 시 편집 권한은 복구되지 않습니다.
3. SQL Editor에서 `schema.sql`을 실행합니다. 실제 DB 정책이 생성됐는지 검증합니다. 기존 프로젝트에 실행하면 안 됩니다.
4. Project URL과 **publishable key**를 `config.js`에 작성합니다. **service_role/secret 키를 절대 붙여넣지 마세요.** publishable key는 클라이언트에 공개되는 것이 정상입니다.
5. `index.html`, `script.js`, `styles.css`, `config.js`를 기존 GitHub Pages의 `t06/` 폴더에 올립니다. `schema.sql`은 참고용 소스이며 공개해도 비밀값이 없도록 작성했지만 기존 프로젝트 비밀은 넣지 마세요.
6. 저장→새로고침→같은 값, 계획 수정→이전 기록, 할 일 상태 전환, 실행 기록, 집계값, 읽기 전용 공개 링크를 검증합니다.

## 주의
- URL로 공유된 **공개 계획**은 익명 방문자가 읽을 수 있습니다. 민감한 업무/개인정보를 입력하지 마세요.
- 데이터는 실제 Supabase DB에 저장되며 로그인 없이 사용하도록 익명 세션을 만들지만, 세션을 분실하면 과거 데이터 수정 권한을 복구하기 어렵습니다.
- 할 일 완전 삭제는 실행 기록도 삭제합니다. "완료를 되돌리기"는 삭제가 아니라 상태 변경이므로 기록이 중복으로 생기지 않습니다.
- 배포 전에 SQL/RLS, 익명 로그인, 타 사용자 편집 차단을 검증하세요.
- 초기 코드이므로 현재 실제 DB와의 연결, 실측 검증, 최종 과제 제출은 미완료 상태입니다.
