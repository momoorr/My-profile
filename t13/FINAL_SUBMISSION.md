# T13 · MOA 운영 콘솔 — 최종 제출란 복사용

## 이번에 만든 것

기업교육 운영 담당자를 위한 웹 애플리케이션 ‘MOA 운영 콘솔’을 완성했습니다. 가상 교육생 문의를 접수하고 목록·필터로 조회할 수 있으며, 공식 안내자료에 근거해 공통 안내·정보 확인 필요·담당자 확인 필요·개별 상담으로 분류합니다. 공식 근거가 있는 문의만 답변 초안을 제시하고, 운영자가 초안을 저장·검토·승인한 후 처리 완료로 표시합니다. 근거가 부족하거나 개인별 확인이 필요한 문의는 답변을 보류하고 추가 확인을 요청할 수 있습니다. 실제 답변 발송이나 실시간 AI 호출이 없는 시연용 앱입니다.

## 확인하는 방법 · 3단계 이내

1. ‘과제 제출 위치’ 등록 → 답변 초안 저장 → 공식 자료 확인 체크 → 검토 승인 → 처리 완료. ‘공통 안내’와 최종 ‘처리 완료’ 표시가 나오면 통과입니다.
2. ‘최종 프로젝트 방식’ 등록 → 검토 메모 작성 → 추가 확인 요청. ‘정보 확인 필요’로 분류되고 미확인 일정·절차를 안내하지 않으면 통과입니다.
3. ‘개인 출결 확인’ 등록 → 검토 메모 작성 → 추가 확인 요청. ‘담당자 확인 필요’로 분류되고 출결을 임의로 조회·추정하지 않으며 승인할 수 없으면 통과입니다.

## 바뀐 점과 그 이유

1차에서는 문의 접수·목록과 규칙 기반 분류까지 구현했습니다. 2차에서 초안 수정·저장, 공식 자료 확인 체크, 검토 승인과 처리 상태 관리까지 추가했습니다. 근거 없는 내용을 확인 없이 답변하거나 승인하는 일을 줄이기 위해 승인 조건과 재검토 과정을 나눴습니다. 최종 단계에서는 이미 공개된 코드를 유지하고 실제 시연 절차, 검사 기록, 발표 자료를 보강해 다른 사람이 재현하기 쉽게 정리했습니다.

## AI에게 맡긴 일과 내가 판단한 일

AI는 웹 화면, JavaScript 기반 문의 분류 및 상태 관리 코드, 입력 오류 처리, 검증 시나리오 구성과 문서·발표 자료 제작을 도왔습니다. 저는 기업교육 운영 담당자를 핵심 사용자로 정하고 핵심 기능을 세 가지로 제한했습니다. 특히 공식 근거 없는 답변의 승인 제한과 사람이 최종 검토하는 흐름을 우선했고, 인증·실시간 AI·자동 발송은 이번 시연 범위에서 제외하기로 판단했습니다. 논문 결과나 정적 분류 규칙을 실제 서비스 정확도로 과장하지 않도록 표현을 검토했습니다.
