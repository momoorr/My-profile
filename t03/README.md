# ALEPH T03 — 한 장 스튜디오

공유용 SNS 카드 이미지를 만드는 웹 편집기입니다. **회원가입·서버·외부 라이브러리 없이** 정적 파일로 실행됩니다.

## 포함 파일

- `index.html` : 편집기 UI
- `styles.css` : 화이트·차콜·하늘색 디자인, 반응형 화면
- `script.js` : PNG/JPEG 안전 불러오기, 문구 편집·위치, 비율·미리보기·내보내기, 템플릿 CRUD, JSON 백업·복구
- `sample-images/` : 직접 코드로 만든 테스트용 PNG 2개 + JPEG 1개
- `example_square.png`, `example_portrait.png`, `example_story.png` : 편집기로 **실제로 내보내 검증한 완성 이미지 3개**
- `DEV_TEST.md` / `REGRESSION.md` : 로컬 자동 검사 기록과 결함 수정 전후 재검사
- `TEST_LOG.md` : 배포 이후 직접 확인할 수 있는 제출용 체크리스트
- `ASSET_CREDITS.md` : 이미지 출처와 개인정보 처리 안내

## 1. 실행 방법

- ZIP 압축을 풀고 **`aleph_t03/index.html`** 더블클릭
- 테스트용 PNG·JPEG를 불러오거나 기하학·원형·선형 예제 배경 버튼 클릭
- 문구와 크기·색·위치 조정 → 1:1·4:5·9:16 선택 → PNG 다운로드
- 템플릿 이름 지정 후 저장 → 저장한 항목 불러오기·수정·삭제 가능
- `JSON 백업` / `JSON 불러오기`로 편집 상태 및 템플릿까지 복원 가능

**참고:** 각 도메인의 브라우저 저장소를 사용합니다. `file://`의 저장 허용 여부는 브라우저 환경에 따라 다르므로 **GitHub Pages에 배포한 뒤** 저장·새로고침 복구를 최종 확인하세요.

### PowerShell로 GitHub에 올리기

기존 `My-profile` 저장소를 그대로 사용하며 **T01/T02 파일을 건드리지 않습니다.**

압축 해제 후 파일 위치가 `C:\Users\<사용자>\Downloads\aleph_t03\index.html`인 경우:

```powershell
cd "$env:USERPROFILE\Downloads\My-profile-upload"
Copy-Item "$env:USERPROFILE\Downloads\aleph_t03" ".\t03" -Recurse -Force
Get-ChildItem .\t03
git add t03
git commit -m "Add T03 card studio editor"
git push origin main
```

접속 주소(배포 **후** 확인): `https://momoorr.github.io/My-profile/t03/`

제출할 소스 주소는 `git rev-parse HEAD`로 **40자리 전체 SHA**를 확인한 뒤 `https://github.com/momoorr/My-profile/commit/<40자리 SHA>`를 사용하세요. 아직 배포한 주소나 커밋이 없는데 미리 제출하지 마세요.

## 2. 사용 규칙과 안전성

- PNG/JPEG **파일 서명(signature)** 확인 및 실제 이미지 디코딩이 성공해야 반영됩니다. 확장자만 PNG인 가짜 파일, GIF 등의 입력은 기존 화면을 유지하며 거절합니다.
- **12MB 이하**의 파일을 받고, 160자/12줄을 넘는 문구는 이전에 정상 편집된 미리보기를 보존하며 수정 안내를 표시합니다.
- 원본 사진의 EXIF 메타데이터는 미리보기·저장용 이미지를 다시 인코딩할 때 제외됩니다. PNG의 투명도는 흰 배경에 합성되므로 원본과 달라질 수 있습니다.
- 1:1 = 1080×1080, 4:5 = 1080×1350, 9:16 = 1080×1920. **같은 캔버스 데이터**를 미리보기와 PNG 출력에 사용하므로 화면·파일의 픽셀 결과가 일치합니다.
- 문구가 길면 canvas 내부에서 안전하게 줄바꿈·글자 크기 자동 조정을 진행합니다. 위치는 %로 관리합니다.
- 등록된 템플릿에는 배경 이미지, 글, 색상, 글자 크기, 위치, 비율이 저장됩니다. 브라우저 저장소 용량 제한이 있으면 오류를 표시하고 JSON 백업을 권장합니다.
- JSON 복원 시 버전·필수 필드·템플릿 수·이미지 형식·**저장된 모든 이미지의 실제 디코딩**을 먼저 검사합니다. 하나라도 실패하면 전체 복원은 취소되고 **현재 작업이 유지**됩니다.
- 공개 페이지에서 업로드한 개인 이미지와 템플릿을 서버로 전송하지 않습니다. 다만 **JSON 백업에 사진 원문에 해당하는 인코딩 데이터가 포함될 수 있으니** 다른 사람에게 공유하기 전 확인하세요.

## 3. 제출 전 직접 실행할 검사

1. 새 시크릿 창에서 공개 결과 URL과 정확한 GitHub 커밋 URL이 열리는지
2. PNG·JPEG 각각 업로드 → 긴 문구 입력 → 글자 위치·색·크기 변경이 즉시 미리보기에 반영되는지
3. 잘못된 PNG·GIF 선택 → 기존 배경과 문구가 사라지지 않는지
4. 1:1, 4:5, 9:16 각각 PNG 다운로드 → 화면과 파일의 **문구 위치·크롭·줄바꿈** 일치하는지
5. 12가지 극단 입력 검증 결과와 수정 전·후 결함 기록 확인 (`DEV_TEST.md`, `REGRESSION.md`)
6. **자신의 브라우저에서** 템플릿 3개 생성·수정·삭제·불러오기 → 새로고침 후 유지 확인
7. 정상·손상·필수 항목 누락 JSON 가져오기 → 정상 복원, 잘못된 파일 거부, 기존 편집 유지 확인
8. 서로 다른 3가지 결과 이미지 확인, 출처 기록, 공개 화면 및 ZIP/JSON에 개인·비밀 원문 없는지 확인
9. 콘솔 오류 0개 확인하고 실제 검사 결과를 `TEST_LOG.md`에 기입

## 4. 과제 제출 항목

- 결과물 URL: **배포 후 실제 확인한** Pages 링크
- 소스 URL: **최종 전체 커밋 SHA URL**
- 4줄 사용·통과 확인: 어디로 / 무엇을 하나(3단계 이내) / 통과 상태 / 안 될 때
- 3줄 AI와 내 판단: AI에게 맡긴 일 / 내가 직접 판단한 일 / AI 제안을 따르지 않은 일(있다면 이유)
- 증거 파일: `TEST_LOG.md`, `DEV_TEST.md`, `REGRESSION.md`, 3개 결과 PNG, 필요시 정상/손상 JSON 테스트 자료

> 자동 검증 기록은 **로컬 브라우저 UI 자동 테스트**이며, 사용자가 온라인 배포 후 직접 수행한 검사로 둔갑시키지 않습니다.
