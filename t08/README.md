## 1. 무엇을 만들었나

기존 자기소개 페이지는 로그인 없이 공개하고, T08 별도 페이지에서는 **패스키로 인증된 사용자만 서버에 저장된 비공개 자료를 조회**할 수 있도록 구현했다. 비공개 내용은 정적 HTML에 넣지 않았다.

- **공개 영역:** 소개 페이지와 비공개 자료 분류명 3개만 표시
- **비공개 영역:** 가상 프로젝트 메모, 가상 지원 목록, 가상 회고 — 서버에 저장된 테스트 자료 3건
- **최초 계정 확인:** 이메일 링크 사용. 이메일 로그인만으로는 비공개 자료 접근 불가
- **인증:** Supabase Auth 패스키 등록·로그인·목록·이름 변경·삭제
- **자료 접근:** Edge Function `t08-private-read`가 인증 상태와 사용자 ID를 확인하고 해당 계정의 자료만 반환
- **저장:** Supabase PostgreSQL `public.t08_private_items` (`owner_id`로 계정 구분)

**검증 범위 주의:** 사용한 계정에는 이전 비밀번호 로그인 이력이 있으므로 계정 자체에 비밀번호가 전혀 없는 상태까지 검증한 것은 아니다. T08 화면에서는 비밀번호 없이 패스키로 로그인한다.

## 3. 재현·통과 확인 방법

### A. 공개 화면과 비공개 본문 분리

- **어디로 가나요:** [T01](https://momoorr.github.io/My-profile/), [T08](https://momoorr.github.io/My-profile/t08/)
- **무엇을 하나요:** 로그아웃 상태에서 두 페이지를 열고 비공개 공간의 세 가지 분류명을 확인한다.
- **무엇이 보이면 통과:** 소개와 분류명은 보이지만 비공개 본문은 보이지 않는다.
- **안 될 때:** 강력 새로고침으로 최신 페이지를 열고 브라우저 오류를 확인한다.

### B. 패스키 로그인 후 서버 자료 조회

- **어디로 가나요:** T08 페이지, 사전에 등록된 실습 계정의 Windows Hello 환경
- **무엇을 하나요:** `패스키로 로그인` → Windows PIN 인증 → `비공개 자료 서버 조회 검사`
- **무엇이 보이면 통과:** `서버 조회 성공: 3개`와 서버 테스트 자료 본문 3개
- **안 될 때:** 계정과 등록된 패스키, 요청 오류 코드를 확인한다. HTML에 테스트 자료를 직접 추가해 통과로 처리하지 않는다.

> 평가자가 별도 계정으로 접속하면 작성자의 비공개 자료가 나타나지 않는 것이 정상이다. 개인 계정 또는 토큰을 공유하지 않는다.

### C. 비로그인 요청 차단

- **어디로 가나요:** Chrome 시크릿 창
- **무엇을 하나요:** `https://kdhopbqqmfbmnqipkwcc.supabase.co/functions/v1/t08-private-read`로 직접 접속한다.
- **무엇이 보이면 통과:** `{"error":"authentication_required"}` 응답. Network에서는 HTTP `401` 확인
- **안 될 때:** 로그인 상태가 아닌 시크릿 창인지 확인한다.

### D. 패스키 없는 이메일 인증 세션 차단

- **어디로 가나요:** T08 페이지
- **무엇을 하나요:** 로그아웃 후 이메일 확인 링크로만 로그인하고 **패스키 로그인 없이** `비공개 자료 서버 조회 검사` 클릭
- **무엇이 보이면 통과:** 서버가 HTTP `403`을 반환하고 비공개 본문이 표시되지 않는다.
- **안 될 때:** 이전 패스키 세션이 남아 있는지 확인한다.

### E. 계정별 자료 분리

- **어디로 가나요:** Supabase SQL Editor 및 T08 인증 화면
- **무엇을 하나요:** 실습 데이터가 `총 6건 / 소유 계정 2개`임을 확인하고, 다른 계정 전용 문구를 구별되게 수정한 뒤 현재 계정에서 조회한다.
- **무엇이 보이면 통과:** 현재 계정의 `3건`만 표시되고 다른 계정 전용 문구가 나타나지 않는다.
- **안 될 때:** 데이터의 `owner_id`와 현재 로그인한 사용자 ID가 일치하는지 확인한다.

> 이번 검증은 **현재 계정에서 다른 계정 자료가 노출되지 않음**을 확인한 것이다. 다른 계정에서 반대로 조회하는 양방향 검사는 완료하지 않았다.

### F. 패스키 하나 삭제 후 남은 패스키 사용

- **어디로 가나요:** T08 `패스키 등록·관리`
- **무엇을 하나요:** 2개 등록 상태에서 Google Password Manager 항목 삭제 → Windows Hello 항목 1개 유지 → 로그아웃 → Windows Hello PIN 로그인 → 서버 자료 조회
- **무엇이 보이면 통과:** `1개 등록됨`, `서버 조회 성공: 3개`
- **안 될 때:** 마지막 패스키를 삭제하지 않고 오류 메시지를 확인한다.

### G. Challenge 변경

- **어디로 가나요:** Chrome 개발자 도구 → Network
- **무엇을 하나요:** 로그인마다 `options` 요청의 Challenge를 비교한다. 원문은 공개하지 않는다.
- **무엇이 보이면 통과:** 두 로그인에서 서로 다른 Challenge가 발급되고 각 `options`/`verify` 요청은 HTTP `200`
- **안 될 때:** `Keep log`를 체크하고 로그아웃 → 다시 로그인하는 별도 인증 시도를 기록한다.

> Challenge가 매번 달라지는 것과 **기존 Challenge 재사용이 거부되는 것**은 별도의 보안 검증이다.

## 4. 실제 검증 결과

| 항목 | 결과 | 검증 근거 |
|---|---|---|
| 공개·비공개 영역 분리 | 성공 | 공개 화면에는 분류명만 노출 |
| 패스키 2개 등록 | 성공 | 등록 목록 2개 확인 |
| Windows Hello 패스키 로그인 | 성공 | PIN 로그인, `options 200`, `verify 200` |
| 인증 후 자료 3건 조회 | 성공 | 서버 조회 성공 메시지와 실제 가상 자료 3건 |
| 비로그인 요청 차단 | 성공 | HTTP 401 / `authentication_required` |
| 이메일 인증만 수행한 접근 차단 | 성공 | HTTP 403 |
| 계정별 자료 분리 | 현재 계정 기준 성공 | 총 6건/2계정 중 3건 조회, 타 계정 문구 미노출 |
| 패스키 1개 삭제 후 로그인 | 성공 | Windows Hello 1개 남긴 뒤 재로그인 및 3건 조회 |
| 로그인마다 새 Challenge 발급 | 성공 | 두 번의 Challenge 값이 다름 |
| 삭제된 패스키로 로그인 거부 | **미검증** | 삭제된 패스키를 이용한 로그인 시도는 완료하지 않음 |
| 두 패스키 각각 독립 로그인 | **일부 미검증** | Windows Hello 성공, 휴대폰 방식은 오류 |
| 기존 Challenge 재사용 거부 | **미검증** | `verify` 재전송에서 CORS 오류 발생. 서버 거부를 확인하지 못함 |
| 로그아웃 전 토큰의 재사용 거부 | **미검증** | 로그아웃 뒤 화면에서 자료가 사라지는 동작만 확인 |
| 비밀번호 없는 신규 계정 생성 | **미검증** | 기존 비밀번호 로그인 이력이 있는 계정 활용 |

## 5. 문제 발견과 수정

- **패스키 목록 중복 표시:** `2개 등록됨`인데 목록이 4줄로 표시되는 현상을 확인했다. 비동기 요청이 겹칠 때 최신 응답만 화면에 반영하고 동일 ID 중복을 제거하도록 수정했다. 강력 새로고침 후 목록 2개가 유지되는 것을 확인했다.
- **휴대폰 패스키 오류:** Windows 보안 창에서 알 수 없는 오류가 발생했다. 반복 실패 후 정상 작동하는 Windows Hello만 이용하여 나머지 검증을 진행했다.
- **Challenge 재전송:** 이미 성공한 `verify`를 브라우저 도구로 재전송했으나 CORS 오류가 발생했다. CORS 오류를 **재사용 차단 성공의 근거로 기록하지 않았다.**

## 6. AI와 내 판단

- **AI에게 맡긴 일:** 구현 코드 초안, 수정안, 오류 원인 가설과 검사 절차, 결과 정리 지원
- **내가 판단한 일:** 브라우저와 Supabase에서 실제 HTTP 결과·자료 조회·계정별 분리·삭제 후 재로그인을 확인하고 성공/실패/미검증을 나누어 기록
- **AI 말을 안 들은 일:** 휴대폰 패스키 오류가 반복되자 무리하게 계속 시도하지 않고, 정상 작동하는 Windows Hello 검사로 범위를 조정했다. CORS 오류나 미검증 항목을 성공이라고 처리하지 않았다.

## 7. 제출 증거 및 주의

- 남은 패스키 `1개 등록됨` + 서버 자료 `3개 조회` 화면
- Network `options` / `verify`가 `200`으로 처리된 화면
- 두 번의 로그인에서 Challenge 값이 달라졌음을 비교한 기록
- 비로그인 `401`, 패스키 미인증 `403`, 계정별 자료 미노출 확인 기록

이 문서는 **실제로 확인한 결과**와 **미완료 검증 항목**을 구별한다. 개인 이메일, 인증 토큰, 원본 Challenge, 비밀 키 등은 공개하지 않는다.
